# DECISIONS

- D001：固定用户指定技术栈；本轮先纯 Dart 领域包，不抢先生成 UI。
- D002：用 pdfplumber 线框单元格提取进行真实 PDF 验证；Python 仅为桌面证据适配器。
- D003：保留 PDF 学期日期及 20 周；周起始日 unknown。以用户明确选择决定周计算，不按当前日期猜“第几周”。
- D004：单元格节次为缺省；课程内部 `(9-10节)` 明确覆盖行头 9—11；概率统计A 保留行头 9—11。
- D005：以原文每段独立排课；同课换教室不覆盖；未排课英语条目保留待处理。
- D006：未知字段统一 unclear；空备注与缺失字段不同。页脚声明学分但记录通常无学分，不能把末尾 64/32 等总学时当学分。
- D007：批准 ACR-001，教学班/证据等通过导入元数据保留，不擅改用户既定实体。
- D008：角色是依次执行的逻辑职责；不运行后台多代理。
- D009：批准 ACR-002：一源一个版本化草稿流、来源命名空间实体 ID、确认后冻结；不同 PDF 的合并延后，禁止覆盖已有记录。
- D010：数据库包独立于纯领域包，Repository 抽象在 schedule_core，实现与 Drift 生成代码在 schedule_storage；文件路径由应用层提供。
- D011：草稿历史、排除理由、来源证据持久化；确认事务包含正式实体、周数组和提交标记，任何数据库异常全部回滚。
- D012：首版 schema v1 导出冻结，重开不重建；未知版本拒绝打开并保留文件。
- D013：待办可保存任意分钟和重叠事件，数据库不替用户决定时间冲突；通知与重复事件调度留在后续阶段。
- D014：跨进程持久化验证使用预先构建的独立读取程序，避开 Windows 已加载 DLL 无法替换的问题；测试临时库结束后清理。
- D015：批准 ACR-003（ANDROID_PLAN）：用 PDFium 字形坐标支持手机 PDF 提取；原生字序保留英文空格、逗号及换行。只增加 adapter 标签，不迁移 schema。
- D016：先用 5 项领域测试建立时间轴/冲突行为，再接页面。未知钟点课程单列；提醒不使用虚构时间。
- D017：首版提醒使用 Android 非精确本地通知和 7 天滚动窗口，明确限制，不额外索取精确闹钟权限。通知异常不损失已保存日程。
- D018：Android 7.0+；通用 APK 覆盖 Flutter 支持的 Android 架构；本地测试签名。设备验收独立于桌面/Widget 测试，未连接设备不宣称运行通过。

## ACR-004 / D019：2026-10-08 用户授权修复按日期停课与星期一起算
增加ClassDayOff与SemesterSnapshot.daysOff（空列表向后兼容），SettingsRepository增加校历设置和停课日增删接口。schema v2只增加class_days_off表；v1升级仅CREATE新表，保留课程、待办、作息与导入审计。原v1 schema基线不覆盖，新增v2基线及真实v1数据升级测试。
按具体学校日期过滤常规课程，周表数量、Today、缺作息列表、冲突和通知共用领域过滤。个人待办照常，不删除排课规则或修改activeWeeks。撤销停课后恢复原课。当前仅明确停课日期，不猜测连休或调休补课。
用户纠正星期一为周起始：正式学期第一周起点通过UI设为2026-08-31，结束2027-01-16和20周不变，手动偏移归零；PDF/导入历史保留原样。不能只把8/30的weekStartDay改成1造成整体错周。新增可见校历编辑入口，不硬编码学校日期或自动修改所有用户数据。


## D020：按日期覆盖课程（用户请求，2026-10-08）
来源采用当前学期指定日期的原始排课，不递归跟随其他调课或停课；目标覆盖优先于停课，来源日不变。每个目标日期仅一条覆盖，保存前展示来源周次/星期、目标和课程，撤销恢复原规则。周表只显示未完成待办，以实际开始时刻定位，短待办保留可读可点击高度。数据库v3新增映射表，保留v1/v2升级路径。


## D021 单节调课（2026-10-12 用户确认）
来源为原始排课指定日期及节次子区间，默认移走来源所选节次，可保留。目标按等长节次覆盖，仅拆除重叠区间，保留两端。单节优先于整日覆盖和停课；不递归复制其他调课。目标/来源已有重叠单节调课拒绝并提示先撤销，避免含糊优先级。数据v4新增表；撤销恢复动态基础排课。
